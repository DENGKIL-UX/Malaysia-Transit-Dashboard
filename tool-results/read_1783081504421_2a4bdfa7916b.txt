     8→
     9→## 1. Visual Theme & Atmosphere
    10→
    11→**Product:** RapidStats MY — Malaysian public transit ridership dashboard
    12→**Mood:** Cinematic dark, data-dense, honest, authoritative
    13→**Density:** High information density with clear visual hierarchy
    14→**Reference:** Dark-mode data observability dashboards (Grafana dark, Linear dark)
    15→
    16→**Philosophy:**
    17→- Dark surfaces reduce eye strain during extended data monitoring sessions
    18→- Green accents signal "transit / GO" without implying false positivity or urgency
    19→- Every data claim is attributed — source badges, confidence flags, freshness timestamps
    20→- No fake "real-time" claims — data age is always visible in the status bar
    21→- Glassmorphism adds perceived depth without heavy drop shadows
    22→- CSS-only animations preserve 60fps performance (no JS animation libraries)
    23→
    24→**Signature element:** CSS train animation — a 12-second looping silhouette that
    25→passes horizontally through the hero section. Zero JavaScript, pure keyframes.
    26→This is the brand's visual identity and must never be replaced with a GIF,
    27→SVG animation, or JavaScript library.

   102→### 2.6 Color Rules
   103→
   104→1. **Never use pure black** (`#000000`). Always use `--bg-base` (`#070e07`) as the darkest surface.
   105→2. **All card borders** use `border border-white/10`. Never solid white borders.
   106→3. **Glassmorphism formula:** `bg-white/5 backdrop-blur-md border border-white/10`
   107→4. **Transit line colors** are reserved for their respective lines. Do not reuse `--line-kajang` for a generic "warning" state.
   108→5. **Green accent** (`#85AB8B`) is for the brand and positive indicators only. It does NOT mean "real-time" or "live."
   109→6. **Orange** is the universal warning color — estimated holidays, stale data, overdue dates.
   110→7. **Red** is reserved for critical states — overdue >30 days, confirmed holidays, negative deltas.

   145→
   146→### 3.3 Typography Rules
   147→
   148→1. **All numeric values** must use `tabular-nums` — no proportional digits anywhere.
   149→   This ensures columns of numbers align vertically.
   150→2. **Headings** use negative letter-spacing (`tracking-tight`) for visual density.
   151→3. **Captions and micro text** use positive letter-spacing + `uppercase` for scannability.
   152→4. **No bold on body text.** Weight 600 is reserved for headings and KPI values.
   153→5. **Text color** always uses the opacity tokens from section 2.5. Never hardcode
   154→   `text-[#6b7f68]` directly — use the semantic role.

   583→## 7. Do's and Don'ts
   584→
   585→### Do
   586→
   587→- Use `tabular-nums` for ALL numeric values — dates, ridership counts, percentages, delta values
   588→- Show data source attribution on every metric (source badge, footer line)
   589→- Flag uncertain dates with the warning triangle and orange color
   590→- Preserve the CSS train animation keyframe and duration exactly as defined in section 4.7
   591→- Use the standardized white/N opacity tokens from section 2.5 — do not invent new opacities
   592→- Use `animate-fade-in-up` with staggered delays for card entrances
   593→- Use glassmorphism (`bg-white/5 backdrop-blur-md border border-white/10`) for content cards
   594→- Show "Data recorded Xd ago" timestamps for data freshness transparency
   595→- Use `rounded-2xl` (16px) for all major card containers
   596→- Use semantic color tokens from this document, never raw hex values in components
   597→
   598→### Don't
   599→
   600→- Add drop shadows to cards (use border luminosity and background layering)
   601→- Use pure black (`#000000`) anywhere — always use `--bg-base`
   602→- Claim "real-time" without a visible freshness timestamp
   603→- Hardcode holiday dates — always fetch from the holiday API chain
   604→- Introduce Framer Motion, GSAP, Lottie, or any JS animation library
   605→- Modify the `train-pass` keyframe duration (12s), easing (cubic-bezier), or transform values
   606→- Use indigo or blue as a primary accent color (blue is reserved for weekend dots and Putrajaya line only)
   607→- Use `eslint-disable` comments to suppress lint rules
   608→- Change the Recharts Area `dot={false}` setting (dots on the line chart would be noisy)
   609→- Add border-radius values other than the standard set: `rounded-lg` (8px), `rounded-xl` (12px), `rounded-2xl` (16px), `rounded-full`

   727→### 9.3 Token Application Rules
   728→
   729→1. **Always** use `var(--token-name)` in CSS custom properties — never hardcode
   730→   hex values directly in component className strings.
   731→2. **Exception:** Tailwind utility classes like `text-amber-400` or `bg-sky-400`
   732→   are acceptable for transit line colors since they map 1:1 to the tokens.
   733→3. **White opacity:** Use the standardized set from section 2.5. If a needed
   734→   opacity is not listed, use the nearest available one.
   735→4. **Border radius:** Only use `rounded-lg` (8px), `rounded-xl` (12px),
   736→   `rounded-2xl` (16px), or `rounded-full`. No other values.
   737→5. **Spacing:** Follow the 4px base unit. Common values: 4, 8, 12, 16, 20, 24,
   738→   32, 40px. Use Tailwind spacing scale (p-1 through p-10, gap-1 through gap-10).
   739→6. **Animation delays:** Use multiples of 80–100ms for staggered entrances.
   740→   First card: 0ms or 100ms. Each subsequent card: +100ms.
